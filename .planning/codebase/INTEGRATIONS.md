# External Integrations

**Analysis Date:** 2026-05-20

## Summary

Nest has one primary external backend: Supabase, which provides authentication, a PostgreSQL database, file storage, and RPC functions. All Supabase interaction flows through a single client instance at `src/lib/supabase.js`. There are no other third-party API integrations, no analytics services, no email providers configured at the code level, and no payment processors.

## APIs & External Services

**Backend-as-a-Service:**
- Supabase — authentication, database queries, file storage, RPC calls
  - SDK/Client: `@supabase/supabase-js` 2.105.4
  - Client singleton: `src/lib/supabase.js`
  - Auth env var: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`

## Data Storage

**Database:**
- Supabase PostgreSQL (hosted)
  - Connection: `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` (anon key, row-level security expected)
  - Client: `@supabase/supabase-js` — no ORM; raw `.from('table').select()` queries
  - Tables in use:
    - `profiles` — user profile records (id, full_name, avatar_url, unit_id); queried in `src/context/AuthContext.jsx`
    - `units` — apartment/unit records (id, name, invite_code); queried in `src/context/AuthContext.jsx`, `src/pages/Apartment.jsx`
    - `expenses` — expense records; queried in `src/pages/Expenses.jsx`
    - `groceries` — grocery list items; queried in `src/pages/Groceries.jsx`
    - `events` — calendar events; queried in `src/pages/Calendar.jsx`
    - `interests` — roommate interest/preference records; queried in `src/pages/Interests.jsx`

**File Storage:**
- Supabase Storage — `receipts` bucket for expense receipt image uploads
  - Upload: `src/pages/Expenses.jsx` via `supabase.storage.from('receipts').upload(...)`
  - Public URL retrieval: `supabase.storage.from('receipts').getPublicUrl(filePath)`

**Caching:**
- None — no Redis, Memcached, or in-memory cache layer. localStorage is used only for theme preference (`localStorage.getItem('theme')` in `src/main.jsx`).

## Authentication & Identity

**Auth Provider:**
- Supabase Auth (email/password)
  - Sign up: `supabase.auth.signUp({ email, password, options: { data: {...} } })` — `src/pages/Login.jsx`
  - Sign in: `supabase.auth.signInWithPassword({ email, password })` — `src/pages/Login.jsx`
  - Sign out: `supabase.auth.signOut()` — `src/pages/More.jsx`
  - Session management: `supabase.auth.getSession()` + `supabase.auth.onAuthStateChange()` — `src/context/AuthContext.jsx`
  - User metadata (`user_metadata`) carries `signup_type`, `unit_name`, `invite_code` for post-signup unit assignment self-healing logic (`src/context/AuthContext.jsx:62-102`)
  - No OAuth/SSO providers detected in code

**Session state:** Managed in `AuthContext` (`src/context/AuthContext.jsx`), exposed via `useAuth()` hook.

## RPC Functions

**Supabase RPC calls:**
- `get_unit_by_invite_code(code)` — looks up a unit by its invite code; called in `src/context/AuthContext.jsx:88` and `src/pages/Apartment.jsx`

These are Postgres functions defined in the Supabase project; no client-side definitions exist.

## Environment Configuration

**Required env vars (defined in `.env.example`):**
- `VITE_SUPABASE_URL` — Supabase project URL (e.g. `https://xxxx.supabase.co`)
- `VITE_SUPABASE_ANON_KEY` — Supabase anonymous/public key

**Fallback behavior:** `src/lib/supabase.js` falls back to placeholder URL/key if env vars are missing or set to template values, allowing the app to render without crashing. Real Supabase calls will fail silently.

**Secrets location:**
- `.env.local` — local development only, gitignored
- Production secrets managed via Vercel project environment variables (dashboard)
